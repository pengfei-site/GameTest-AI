# 一、文档目的

本文档用于说明 GameTest-AI 项目的工程目录组织方式、模块职责、文件命名规范以及后续目录扩展规划。

主要目的：

1.  统一工程目录组织方式。
2.  明确各模块的职责和边界。
3.  避免不同业务模块之间出现重复实现。
4.  方便后续 STEP 08 及之后的功能开发。
5.  为工程维护、测试和版本管理提供依据。

**注意：** 本文档中的数据库及 Repository 路径来自当前已确认的工程记录；其他目录属于建议规划，最终以实际工程检查结果为准。

# 三、根目录文件说明

| 文件 | 主要职责 |
| --- | --- |
| main.py | 程序启动入口 |
| config.py | 项目运行配置入口（如采用独立配置模块） |
| requirements.txt | Python 项目依赖清单 |
| README.md | 项目介绍、环境配置和运行说明 |
| .gitignore | Git 文件忽略规则 |

配置文件的具体位置需要结合实际工程统一，避免同时维护多份重复配置。

# 四、核心目录职责

## 4.1 app/ —— 应用入口层

负责应用初始化和应用运行入口。

建议职责：

*   初始化应用。
*   加载配置。
*   注册路由。
*   管理应用生命周期。
*   连接业务服务层。

不负责：

*   直接编写数据库 SQL。
*   实现具体文档解析算法。
*   编写复杂业务规则。

## 4.2 core/ —— 核心基础模块

负责项目级公共基础能力。

建议包括：

| 文件 | 职责 |
| --- | --- |
| config.py | 配置加载 |
| exceptions.py | 统一异常定义 |
| logger.py | 日志管理 |

## 4.3 modules/ —— 业务功能模块

负责组织平台的具体业务功能。

建议划分：

| 子目录 | 业务职责 | 对应建设阶段 |
| --- | --- | --- |
| project/ | 项目管理 | 已有基础数据能力 |
| document/ | 文档导入与管理 | STEP 08 |
| requirement/ | 需求分析 | STEP 09 规划 |
| generation/ | 测试用例生成 | STEP 10 规划 |
| test\_point/ | 测试点审核与管理 | STEP 11 规划 |
| report/ | 报告与统计 | STEP 12 规划 |

建议每个业务模块内部逐步形成：

```
document/
├── __init__.py
├── controller.py
├── service.py
├── schemas.py
└── exceptions.py
```

具体文件是否需要拆分，以模块复杂度为准。
